# order_033

## ユーザーの指示
では次のステップに進んでください。

（直前のやり取り：新しい提案手法の最終成績が低い主な原因は深さ0の棄却であり，「棄却の判定を実験して最適な判定を探す」ことを次のステップとして提案した．ユーザーはこれを了承した．）

## 解釈
- 新しい提案手法（OWLv2 + Alpha-CLIP + WordNet）の深さ0の棄却（残すボックスの判定）を探索する．問題の対象が棄却に変わるため，新しい実験 ex021 とする．
- 検出・特徴・VG の木は ex019・ex020 のキャッシュを用いる．新たに計算するのは Alpha-CLIP の crop 入力の特徴だけである．
- 探索する条件（全ての組を itertools.product で評価する）：
  - OWLv2 のボックス数：20個/枚，50個/枚
  - Alpha-CLIP の入力：context1.5，crop
  - 重複・部分の除去：
    - なし
    - クラスごとの NMS（同じ名前で IoU 0.5 以上）
    - クラスごとの NMS + 包含（同じ名前で，小さいボックスの80%以上が大きいボックスに含まれる）
  - 棄却のスコア：
    - joint（確信度 × 物体らしさ．現在の方法）
    - 物体らしさのみ
    - VLM の確信度のみ
    - 部分木の確率の合計（VG の木の COCO の各クラスの部分木の確率の合計の最大値）
    - 部分木の確率の合計 × 物体らしさ
  - θ：dev のスコアの分位点から選ぶ．基準は2通りで，dev の COCO の F値と dev の細かい粒度の hF（vg_subtree）である．
- 評価：test の COCO の F値（ex019 の評価），細かい粒度の hF（ex020 の評価．命名は coarse と vg_subtree），人物の再現率．
- 比較：古い提案手法（DETR + CLIP-B/32）と YOLO11x 単体を，同じ評価のコードで再計算する．
- 命名の手順の条件（vg_subtree の T，τ）は ex020 で選んだものに固定する．深さ0のラベルも変えず，棄却の判定だけを比べる．
- 実行中の追加：
  - **深さ0のラベル：** 人物のボックスを残しても，COCO の80クラスの softmax では person と命名されない（持ち物の名前になる）ことが分かった．そこで，深さ0のラベルの種類 {coco，mass（COCO のクラスの部分木の確率の合計が最大のクラス）} を条件に加えた．古い提案手法にも同じ条件を加えた．
  - **hF で選ぶ θ の偏り：** hF は正解に対応したボックスだけを評価し，誤検出では下がらない．そのため，hF で選ぶ θ は棄却しない方向に偏る．総合の比較には COCO の F値で選んだ θ を用いる．
