# report_012：COCO外の物体の命名の改善（ex011）

## 1. 概要

order_011（ex010）では，YOLO11x に OWLv2 の候補を加えることで，COCO 外の物体の検出は 4.6% → 31.6% になった．しかし，検出した物体のうち正しく命名できたのは8.1%にとどまっていた．

そこで，直前に提案した改善策を，おすすめの順番で実施した（`programs/ex011_open_world_naming/`）．

| 順番 | 提案 | 内容 |
| :---: | :--- | :--- |
| 1 | 提案2：候補の棄却 | OWLv2 の物体らしさ ≥ $`o`$，出力した語のシグモイドの確信度 ≥ $`\gamma`$，面積の80%以上が自身より大きい他の出力ボックスに含まれない，の3つの基準で候補を残す |
| 2 | 提案1：上から下への命名 | 頻出するカテゴリの語とCOCOの80語（合わせて274語）から最初の語を選び，キャプションで絞り込んだ WordNet の木（8121節点）を葉までたどる．兄弟の中でのソフトマックスが $`\tau_s`$ 未満になったら止める |
| 3 | 提案3：語彙の改善 | 物体の部分を表す語を除き，COCO train2017 のキャプションに出る語に限った語彙（435語） |
| 4 | 提案4：VLM の改善 | SigLIP SO400M，クロップを1.5倍に拡大，親の語を含むプロンプト（例：「a photo of a hound, a type of dog」） |

結果は，新しい論文 `paper_v2/main.pdf` に赤字で追記した（3.7節，4.6節，要旨・はじめに・考察・おわりに．8ページ）．

### 実験の条件

| 項目 | 内容 |
| :--- | :--- |
| 基準 | YOLO11x（0.25）のボックス（全構成で共通．シグモイドの累積確信度 τ = 0.05 まで出力）＋ YOLO と重ならない OWLv2 の候補（最大20件） |
| 閾値の選択 | lvis_dev から1000枚を使った．lvis_dev の OWLv2 の推論はこのために新たに実行した |
| 評価 | lvis_test（2148枚，COCO の物体15842件，COCO 外の物体12655件） |
| 指標 | 出力ボックスと GT を IoU 0.5以上で1対1に対応付けた．各語の自身とすべての上位語のうち深さ4以上の Synset で，階層的な適合率・再現率（hP / hR）を求めた．GT と対応しない出力は hP の分母，出力のない GT は hR の分母に含める |
| 閾値の選び方 | 予算 B（1画像あたりに加える候補の数の上限，1・2・5件）ごとに，COCO 外の物体の hR が最大になる組を選んだ．探索した閾値は K，o，γ，包含の有無，τ_s である |

### 閾値の選び方を途中で変えた理由

最初は，全体の hF が最大になる閾値を選んでいた．しかし LVIS の注釈は網羅的でないため，候補を加えると，正しい物体を囲んでいても hP が下がる．その結果，どの構成でも「加えた候補をほぼすべて棄却する（1画像あたり0.1〜0.4件）」閾値が選ばれ，構成どうしを比較できなかった．

そこで実行を止め，予算ごとに選ぶ方式に変えて再実行した．全体の hF で選んだ結果も，参考として `metrics_hF.json` に残している．

- **提案2（棄却）：** B=2 で hR は0.047 → 0.056，適合率は5.4% → 8.1%に上がった．選ばれた閾値は，どの予算でも物体らしさ o ≥ 0.2 だった．包含による棄却は，どの予算でも選ばれなかった（効果なし）．
- **提案1（上から下への命名）：** B=5 で命名は2.3% → 3.1%，適合率は5.2% → 6.5%に上がった．従来の命名に停止規則を加えただけ（p1_flat_stop）では，ほとんど変わらなかった．
- **提案4（SO400M）：** 上から下への命名と組み合わせると，B=5 で命名4.1%，適合率8.1%になった．ベースラインの2.4倍と2.2倍である．一方，同じ SO400M でも，従来の命名では2.1%だった．VLM が強いほど，上から下への命名の効果が大きくなった．
- **全部の組み合わせ：** B=1・B=2 の適合率が17.9%・11.4%で最も高くなった．ただし，B=5 の命名（3.47%）は SO400M だけの構成（4.09%）より低かった．
- **提案3（語彙の限定）：** 従来の命名では，効果がないか，逆に悪化した（B=2 で 1.37% → 0.94%）．
- **COCO の物体：** hR は，候補を加えない場合の0.654から0.66〜0.69に，どの構成でもわずかに上がった．
- **全体の hF：** 候補を加えない場合（0.467）が最も高く，候補を加えるほど下がった（B=5 で0.42〜0.43）．これは，LVIS の注釈が網羅的でないためである．

## 3. 考察

- **棄却と上から下への命名は有効：** 加えた候補の命名の適合率と，COCO 外の物体の命名率をどちらも高めた．
- **大事なのは語の選び方：** 語彙を絞り込んでも効かず，粗い語から順に選ぶことと，VLM を強くすることが効いた．語彙の大きさより，選ぶ順序と停止の仕組みのほうが重要である．
- **絶対値はまだ低い：** 改善後でも，COCO 外の物体の命名は4.1%にとどまる．LVIS の COCO 外の物体には，小さい物体や部分的に隠れた物体が多い．また，閾値の選び方の都合で，加える候補は1画像あたり5件以下に制限している．

## 5. 未解決の論点と次の候補

- **評価データ：** LVIS の注釈が網羅的でないため，加えた候補の適合率は低めに出ている．網羅的な注釈を持つデータセット（Objects365，OpenImages の一部など）で評価することが候補である．
- **上から下への命名の出発点：** 出発点の語（274語）には，area，color，direction などの抽象的な語も含まれている．出発点の選び方を改善する余地がある．
- **停止の閾値：** COCO 外の hR を最大にする選び方では，ほとんどの予算で τ_s = 0（最後まで出力）が選ばれた．粗い語で止める効果を評価するには，hP を重視した選び方も試す必要がある．
- **計算時間：** SO400M の特徴計算は，半精度でも1画像あたり約0.4秒かかる．全体の実行時間は約2時間である．
- **評価の範囲：** seed は42の1つだけで，閾値の選択には lvis_dev の1000枚だけを使った．
- **スライド：** 未作成である．
- **tokens.json：** ファイルがないため，ai-agent による検証は行っていない．
