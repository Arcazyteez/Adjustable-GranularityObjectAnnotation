# report_020：アノテーションのスコアの付与と改善（ex015a），論文・スライドへの反映

## 1. 概要

ex015の粒度可変アノテーションにスコアを付け，そのスコアを改善した．出力はボックスと単語の組だけでなく，次の2種類のスコアを持つ．

- **出力全体のスコア：** そのアノテーションが正しい確率
- **経路上の各単語のスコア：** artifact → … → ski parka の各単語について，その単語が正しい確率

利用者は，前者の閾値で出力の数を，後者の閾値で粒度を選べる．

- **プログラム：** `programs/ex015a_annotation_score/`（`data.py`，`model.py`，`train.py`）．ex015の軽微な追加のため，通し番号015を維持した．
- **設定：** ex015で選んだ設定をそのまま使った（greedy，β = 2，τ = 0.1，ens の文章，人の役割を除く，K = 100）．スコアで棄却するため，物体らしさの下限は設けていない．
- **再学習：** 物体認識モデルと埋め込みモデルは再学習していない．スコアの重み（出力全体は9個，各単語は5個）だけを，検証用の画像で求めた．

## 2. 比較したスコア

| 名前 | 内容 |
| :--- | :--- |
| det（c） | 検出のスコア．YOLO11xの確信度，またはOWLv2の物体らしさ．ex015の棄却に相当する |
| name（q） | 出力した単語の集約した確率．YOLO11xのボックスでは，OWLv2の領域の特徴から求めたクラスの q を使う |
| det_x_name | c × q |
| det_x_name_added | 加えた領域だけ c × q とし，YOLO11xのボックスは c のまま |
| calibrated（提案，式4） | 下の特徴を入力とするロジスティック回帰 |

- **提案のスコアの特徴：** logit(c)，log q，語彙上の確率の最大値（log），エントロピー，単語の深さ，出力元，出力元と logit(c)・log q の交互作用
- **教師：** 検証用の画像の出力のうち，正誤が判定できるもの（18488件，正の割合45.7%）

経路上の各単語のスコア（式5）は，次のように求めた．

- **入力：** log q，単語の深さ，確率の最大値，エントロピー
- **教師：** 検証用の画像で，GTと対応した加えた領域の経路上の各単語（57860語）．正解は，その単語がGTの上位語・自身・下位語であることとした．
- **仕上げ：** 経路の上位からの累積の最小値をとり，細かい語ほどスコアが下がるようにした．

## 3. 評価方法

- **対応付け：** スコアの高い順に，出力をGTへ対応付けた（COCOのAPと同じ方法）．
- **AP：** 閾値を下げながら出力を加えた場合の hR と hP_fed，hP_strict から，適合率を単調にした曲線の面積を AP_fed，AP_strict とした．
- **ECE：** スコアを確率とみなし，正誤が判定できる出力について，10個のビンで期待校正誤差を求めた．
- **閾値：** 検証用の画像で hF_strict（または hF_fed）が最大になる値を選び，テスト用の画像に適用した．
- **保存：** 検証用とテスト用の両方の指標を `metrics.json` に保存した．

### 分かったこと

- **提案のスコアは全ての重みで最良だった：**
  - AP_fed と AP_strict が最も高かった．
  - STでは，検出のスコアだけの場合と比べて，AP_strict が0.171 → 0.197，選んだ閾値での追加精度が9.9% → 16.6%に上がった．
  - ECE は0.145 → 0.028に下がり，スコアの値が正解率とほぼ一致した．
- **命名の確率 q だけでは使えない：**
  - 物体でない領域にも高い値が付き，AP_strict は0.042だった．
  - c × q も，YOLO11xのボックスの q が低いため悪化した．
  - 学習なしで使うなら，加えた領域だけ積にするのが最もよかった（AP_strict 0.171，ECE 0.231）．
- **経路上の各単語の q は過小評価だった：**
  - q の値は正解率より低かった（ECE 0.275）．
  - 式5の校正で ECE は0.041に下がった．
  - 例：STの ski parka の経路は artifact 0.89，clothing 0.89，jacket 0.82，parka 0.62，ski parka 0.43 で，粗い語ほどスコアが高い．
- **改善の幅は限定的である：**
  - AP_strict の差は約0.03だった．
  - hF_fed の最大値は，スコアによらずほぼ同じだった（STで0.49）．
  - 物体でない領域を区別するには，領域そのものを判定する特徴が必要である．

### 実装中の修正

- **重複していた語：** 当初，経路の末尾に同じ単語が繰り返し入っていた．原因は，`greedy_path` が進めなくなった後も最後のSynsetを繰り返すことである．`data._chains` で連続する同じSynsetを除いて再実行した．出力する単語そのものは，ex015と同じである．
- **経路上の単語のスコアの作り方：** 最初は出力全体のスコアのモデルを経路上の各単語にも使ったが，ECE が悪化した（0.287 → 0.339）．両者は推定する確率が異なる（出力全体は「物体かつ正しい」，各単語は「物体である場合に正しい」）．そこで，各単語用のモデルを別に求めた．

## 8. 未解決の論点

- **物体でない領域の区別：** 改善の幅は小さい．領域が物体の全体か一部かを判定する特徴（例：YOLOのボックスとの包含関係，領域の大きさ）を加える価値がある．
- **校正の適用範囲：** スコアの重みはLVISの検証用の画像で求めた．分布の異なる画像では，校正が崩れる可能性がある．
- **ラベルの偏り：** LVISは全ての物体に注釈があるわけではないため，正誤が判定できない出力は校正から除いた．その分，校正は判定できる出力に偏っている．
- **評価の範囲：** seed は42の1つだけである．
- **ai-agent による検証：** `tokens.json` が無いため，行っていない．
